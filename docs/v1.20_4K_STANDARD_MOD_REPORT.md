## 1. Background & Solved Problems

Following confirmation that 4K video recording was functional on the Standard Edition, two user-experience defects were reported:
1. **Severe FOV Crop / Magnification (画面放大)**: 4K recording experienced noticeable crop compared to 1080p 60p, losing the native 28mm wide-angle street view.
2. **Horizontal Panning Vertical Stripe Intrusion (左右移位边缘竖条侵入)**: When moving the camera sideways/panning during recording, corrupted vertical stripes intruded from the left/right frame borders (faster pan = worse intrusion), whereas vertical tilting showed no artifacts.
3. **Firmware Baseline Upgrade**: Migrate and rebuild all improvements onto the latest official **v1.20** firmware.

## 2. Root Cause Analysis

### A. Horizontal Panning Vertical Stripe Intrusion (EIS Division Bug)
- **Mechanism**: In `src/LiveViewProcess.cpp` around `0x5365aa94..0x5365ab34`, which prepares stabilization dimensions and calls `MovieShakeReductionService::SetupMovieShakeReduction` (`0x538b7b3c` in v1.20):
  ```arm
  0x5365aae4: rsbne r4, r6, r8, lsr #1   ; if 4K: Crop Width = (Full Width >> 1) - MarginX
  ```
- **The Bug**: For 4K UHD, the width calculation mistakenly divided `r8` (3840) by 2 (`rsbne r4, r6, r8, lsr #1`), storing halved width (`1920`) into `[r3, #0x778]`. Height (`0x5365aaf8`) had no division bug (`2160 - 2 * MarginY`).
- **The Impact**: When panning horizontally, the Movie Shake Reduction (EIS) service shifted its readout window beyond 1920 pixels, accessing uninitialized DMA line buffer memory and wrapping line strides, producing vertical stripe corruptions. Vertical motion was clean because height was never halved.
- **Resolution**:
  1. Patch `0x5365aae4` to `movne r4, r8` (`3840`, full width).
  2. Completely eliminate electronic stabilization by replacing the tail-call at `0x5365ab34` (`b #0x538b7b3c`) and the entry of `SetupMovieShakeReduction` at `0x538b7b3c` with `bx lr`. This ensures no digital margin shifting or linebuffer corruption can ever occur.

### B. FOV Crop / Magnification (Center Crop Readout Mode)
- **Mechanism**:
  - In 1080p 60p, `SelectSensorDriveMode` (`0x536568d4`) selects **Sensor Mode 4**.
  - In `0x536717b0`, the mode table at `0x536717e0` maps Mode 2, 3, and 4 to **CIS Mode 3**. CIS Mode 3 reads out the **full 26MP APS-C sensor width (6240×3510)** with 3x3 pixel binning, giving 100% native 28mm wide field of view.
  - In contrast, when `IsDebug4KMovie == 1`, 24p selected Mode 5 and 30p selected Mode 6. The jump table at `0x536717e0` mapped Mode 5 & 6 to **CIS Mode 0x12** (the Pentax K-3 Mark III center crop 4592×2584 window), creating a `6240 / 4592 = 1.35x` optical crop.
- **Resolution**:
  - In the jump table at `0x536717e0`:
    - Entry 3 (`0x536717ec`, Mode 5): redirected from `0x53671a94` (CIS `0x12`) to `0x53671a68` (**CIS Mode 3**).
    - Entry 4 (`0x536717f0`, Mode 6): redirected from `0x53671a94` (CIS `0x12`) to `0x53671a68` (**CIS Mode 3**).
  - Both 4K 24p and 30p now read out the full sensor width in CIS Mode 3, producing an exact 1:1 FOV match with 1080p 60p.
